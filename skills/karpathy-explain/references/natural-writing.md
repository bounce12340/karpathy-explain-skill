# 工程解說的自然文字檢查

此檔改編自 [Humanizer-zh](https://github.com/bounce12340/Humanizer-zh) 的編輯原則，不收錄其規則清單或範例。只在**完成事實核對與分層解說後**使用，用來修掉妨礙理解的模板化表達；不是 AI 作者偵測器，也不保證通過偵測器。

## 先保護證據，再修改句子

逐句比對修改前後。保留來源錨點、引文、數字、否定、條件、時間、主體、適用範圍，以及 `[已確認]`／`[實測]`／`[推論]`／`[未知]` 的確定程度。不能把「可能」寫成「一定」，不能把「計畫」寫成「已完成」。不改程式碼、指令、檔案路徑與連結目標；不替作者編造經歷或成果。若原句已清楚，原樣保留。

## 只修真的有問題的表達

1. **直接說明行為**：空泛鋪墊或沒有資訊的讚美會拖慢讀者；用已確認的行為取代，不加虛構數字。
2. **刪掉重複的話**：段首只重述標題、段末只換句話說前句時，留資訊較完整的一句。保留範圍與限制。
3. **讓標題有導航用途**：需要跨「30 秒／3 分鐘／深入」切換時保留層級；不要每段都加裝飾性圖示、編號與提示語。
4. **保留必要語氣**：不用「不像 AI」作為修改理由。比喻、短句、列點、被動句、冒號及「首先」只在空泛、重複、歧義或不合文體時才改。
5. **依讀者語言與地區寫**：繁體中文（台灣）用自然的台灣工程用語；不擅自轉換簡繁，不改專有名詞或 API 名稱。

## 合成示範（不是專案調查結論）

- 套話：「這個精心設計的驗證器，無疑為專案品質提供強大保障。」
  → 可說：「驗證器會檢查技能格式、文件連結與證據行號。」但**只有讀過實際程式碼**且能附來源時才這樣寫。
- 把推論寫成事實：「這個 403 顯然是權限檢查造成的。」
  → 沒有來源時：「403 可能與權限有關 `[推論]`；需要檢查身分與資料歸屬。」

交付前問：改寫後有沒有新增事實、刪掉限制、改變主詞、弄錯語言？如果有，退回修改。

## 選用 Humanizer-zh

若使用者**另有安裝** `humanizer-zh` 且明確要求進一步潤飾中文說明，可在完成工程事實核對後讀它的 `SKILL.md`，只對解說文字做第二輪檢查。它是可選工具；沒有安裝也能依本檔完成工作。帶入其他技能時仍遵守本技能的證據與權限界線，不把使用者程式碼送到未經授權的外部服務。
